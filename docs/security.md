# 权限与安全边界

MiniMcp 以启动它的系统用户身份运行。把服务开放给远程客户端前，先检查系统账号、项目目录、Cloudflare Access 登录策略和本机 `policy.json`。客户端确认是客户端自己的交互；服务端仍按当前会话的执行模式检查每次调用。

## 执行模式

八个工具始终显示在目录中。缺少可选依赖或当前模式不允许写入时，调用会返回错误。

| 操作 | ReadOnly | ProjectEdit | FullAccess |
| --- | --- | --- | --- |
| 读取、列表、搜索及 Git 查询 | 允许 | 允许 | 允许 |
| `apply_patch` 完整预演 | 允许 | 允许 | 允许 |
| 普通源码、文档补丁 | 拒绝写入 | 上限内允许 | 通过基础检查后允许 |
| 删除、移动、关键或未知文件补丁 | 拒绝写入 | 整批拒绝 | 通过基础检查后允许 |
| Bash | 拒绝 | 拒绝 | 允许 |
| 本机查看恢复预览 | 允许 | 允许 | 允许 |
| 本机确认恢复 | 拒绝写入 | 允许 | 允许 |

ProjectEdit 将 `.sh`、`.ps1` 等脚本扩展名、构建和 CI 文件、选中的配置文件，以及带 shebang 或执行权限的文件视为关键文件；未知类型也不能写入。同一补丁混合了普通和受限操作时，整批拒绝。预演中的 `decision` 说明当前模式下能否尝试提交；提交前还要重新检查文件和恢复存储。客户端确认或修改工具参数不能改变这些规则。

模式在一次服务运行中固定。CLI 停止后重新运行，桌面保存策略后停止并重新启动，才能应用新的默认模式。`run --mode` 只覆盖本次 CLI 会话。

## 文件和查询范围

文件工具的参数使用项目内相对路径，拒绝越界、符号链接、junction 和私密路径。受保护的名称包括 `.git`、`.env*`、`.ssh`、`.aws`、`.config`、`.codex`、`.agents`、`.cloudflared`、`tunnel-token` 和常见私钥证书扩展名。读取和补丁处理 UTF-8 文本，单文件最多 256 KiB。

`search_text` 调用本机 ripgrep，搜索前检查范围，排除私密文件和链接，并限制遍历、耗时和输出。三个 Git 工具调用本机 Git 查询受支持的项目根仓库，使用固定的查询参数，忽略默认的系统和全局 Git 配置。MiniMcp 禁用外部 diff、textconv、fsmonitor、自动获取缺失对象和索引刷新写入；结果是对文件当时状态的观察，不是跨文件事务快照。具体限制见 [工具使用](usage.md)。

### Git 配置与外部程序

Git 查询会读取仓库本地 `.git/config` 及其中引用的配置文件。Git 可能按照配置运行外部程序；例如，`git_diff` 比较工作区文件时可能调用 clean filter。程序以 MiniMcp 的系统账号运行，可以访问该账号有权访问的项目外文件和网络。它造成的修改和其他副作用不会生成补丁恢复记录，查询超时或终止也不会撤销已发生的操作。

这一行为适用于 ReadOnly、ProjectEdit 和 FullAccess。Git 工具保留 MCP 的 `readOnlyHint=true` 提示，客户端可能直接执行查询；该提示不能限制 Git 启动的外部程序。使用前请确认仓库本地配置、include 文件、`.gitattributes` 和 filter 程序来自可信来源。

ProjectEdit 拒绝直接修改 `.git/config`、`.gitattributes` 和 `.ps1` 文件，也不允许 Bash；它仍允许在限额内修改普通源码，例如无 shebang 的 `.py` 或 `.js` 文件。如果已有 filter 把这些可编辑文件作为程序执行，Agent 可能先修改文件，再通过 Git 查询触发它。ReadOnly 不允许 Agent 通过补丁修改文件，但查询仍可能运行仓库已配置的程序。

这些路径检查不是操作系统沙箱：硬链接和其他本机进程并发替换文件仍有边界。Local 认证允许本机匿名调用，其他同机进程也可能访问监听端口。`/healthz` 在两种认证模式下都提供本机匿名健康检查。

## 补丁记录与恢复

每次实际 `apply_patch` 都要先保存完整恢复记录，记录包含原始字节，包括未提交到 Git 的内容。记录存储不可用、容量不足或备份失败时，补丁不会作为无记录写入继续执行。记录最多 1000 个槽位和 1 GiB 文件字节；程序不会自动删除旧记录。

提交失败时尝试回滚；如果外部进程同时改动文件、回滚或最终记录保存失败，查看错误中的实际状态和记录，再检查文件，避免盲目重试。客户端中断或断线也可能发生在服务端已开始安装之后。强制结束进程或断电无法保证多文件原子性。

恢复只能从本机 CLI 或桌面操作，先展示完整反向预览并确认。恢复前会再次检查记录和当前文件；有冲突时需要先处理冲突。成功恢复会创建一条新记录，可以再恢复这条记录来撤销。记录目录包含项目原始内容，应限制系统用户访问，并按需要自行备份。

## Bash 和外部服务

FullAccess 的 Bash 以服务账号运行，项目根只是默认工作目录。命令可以访问该账号有权访问的其他文件、程序和网络；Bash 的副作用不包含在补丁恢复记录中。每次调用使用新的非交互 shell，超时或取消后会清理普通子进程。

CloudflareAccess 模式在 `/mcp` 校验 Cloudflare 转发的 JWT 签名、issuer、AUD 和有效期；OAuth 登录和 Access 策略由 Cloudflare 处理。仅在 Access 策略中允许你信任的身份。Tunnel token 能启动对应隧道，应作为凭据保存，避免写进仓库、日志或命令历史。详细部署见 [Cloudflare 指南](cloudflare.md)。
